# 0001. 以网盘内身份文件作为身份锚点

状态：已接受（2026-05-08）

## 背景

同一个夸克用户重新登录（新设备 / 新 cookie）时，系统必须把它合并回同一个 WebDAV 账户。这需要一个跨登录稳定、且能被本系统验证的"夸克身份"。

候选方案：

1. **夸克 API 的用户标识字段**（如 `GET https://pan.quark.cn/account/info` 返回的 user id）。多个开源项目用它做登录校验，但响应里的稳定 id 字段无法实证（`nickname` 可改可重名，不能当身份）。
2. **cookie 内嵌字段**（如 `__uid`）。客户端可伪造，且 `__pus`/`__puus` 会被上游 Set-Cookie 定期轮换，稳定性无证据。
3. **网盘内身份文件**：注册时由 Worker 在网盘根目录写入 `dav-id.txt`，内容是一个高熵随机身份 key；重新登录时读取该文件、按 key 查找既有账户。

## 决策

采用方案 3。账户归属由身份 key 唯一决定；`/account/info` 仅用于向管理员展示昵称等辅助信息，不参与身份判定。

## 后果

- 身份判定不依赖任何未实证的上游接口字段，且跨 cookie 轮换、跨设备稳定。
- **身份文件成为凭证级资产**：拿到该文件等于拿到该账户的 WebDAV 凭据。分享 / 转存身份文件到他人网盘可导致账户被接管。已接受该残余风险，以页面显眼告警缓解；将来可在认领时增加昵称一致性校验作为纵深防御，本决策不阻碍该扩展。
- 身份文件缺失 / 损坏 / 其 key 在 KV 中不存在时，一律视为未注册、重新走注册与审核流程；系统绝不自动认领未知 key（否则自造 key 即可绕过审核准入）。代价是 KV 数据丢失后已有用户需重新注册。
- 用户删除身份文件等于放弃既有账户，需重新注册。
